# 群聊事件跟踪器设计文档

## 概述

群聊事件跟踪器是一个基于 LLM 的智能模块，用于自动识别、跟踪和分析群聊中的热点事件。当多个群聊在短时间内广泛讨论同一事件时，系统会创建独立的事件实例，归档相关内容，分析事件起因和时间线，并在适当时机确认立场。

## 设计目标

1. **自动事件识别**: 从高活跃讨论中识别同一事件
2. **跨群关联**: 关联不同群聊中关于同一事件的讨论
3. **中立分析**: 分析期间保持中立，不表达立场
4. **智能立场确认**: 分析完成后由 Planner 确认立场
5. **时效性隔离**: 事件结束后归档，不再主动注入立场

## 核心概念

### 事件生命周期

```
候选事件 → 信息积累 → 待确认 → 立场活跃 → 复核/冷却 → 已归档
```

**状态说明**:

1. **候选** (Candidate): 检测到潜在事件，等待验证
2. **信息积累** (Accumulating): 正在收集相关消息和证据
3. **待确认** (PendingStanceConfirmation): 分析完成，等待 Planner 确认立场
4. **立场活跃** (StanceActive): 已确认立场，事件仍在活跃讨论中
5. **复核/冷却** (UnderReview): 发现重大反证，重新评估立场
6. **已归档** (Archived): 事件结束，长期保存但不再主动注入

### 事件档案结构

```python
{
    "event_id": "uuid",
    "root_cause": "事件起因（带证据引用）",
    "timeline": [
        {
            "timestamp": "时间戳",

            "sources": ["消息ID列表"]
        }
    ],
    "viewpoints": [
        {
            "faction": "观点流派名称",
            "summary": "观点摘要",

    "status": "当前状态",
    "created_at": "创建时间",
    "archived_at": "归档时间"
}
```

## 工作流程

### 1. 事件发现

**触发条件** (任一群聊需同时满足):
- 10分钟内至少8条相关消息
- 至少3位不同发言者
- 活跃度达到该群30天基线的3倍

**语义聚类**:
- 使用 Embedding 计算消息相似度
- 只有单一语义簇达到门槛才创建事件
- 避免将不同话题误判为同一事件

**跨群关联**:
- 仅在同平台、同机器人账号、同路由作用域内关联
- 语义匹配置信度 ≥ 0.85 才合并为同一事件
- 低于阈值则保持独立事件

### 2. 信息积累

**消息来源**:
- 只处理已通过预处理和过滤的外部群聊消息
- 排除机器人自身消息、通知、被过滤消息
- 私聊消息不纳入 V1

**积累内容**:
- 文本快照（不复制媒体）
- 来源群和消息引用
- 时间戳和发言者信息（去标识化）

**稳定期判断**:
- 连续30分钟无新增关键证据
- 重复消息不重置稳定期
- 证据不足时仍可完成"证据不足"的分析

### 3. 中立参与

**允许的行为**:
- 自然追问和核实来源
- 归纳各方说法
- 表达不确定性

**禁止的行为**:
- 赞同或贬低任一方
- 暗示支持某个观点
- 提前表达立场

**中立性审核**:
- Replyer 生成回复后由 `event_analysis` 模型审核
- 检测到偏向则重写一次
- 仍不合格则使用中性追问模板

**审核覆盖**:
- 主要回复链路: `reasoning_engine.py` → `reply.py`
- 其他输出路径: 在 `send_service.py` 统一检查
- 防止插件等绕过中立限制

### 4. 事件分析

**分析任务** (`event_analysis`):
- 使用独立的模型配置
- 未单独配置时继用 `utils` 模型
- 通过后台队列执行，不阻塞消息处理

**分析内容**:
1. **事件根因**: 讨论起因和背景
2. **时间线**: 关键节点和发展过程
3. **观点流派**: 识别对立观点并分类
4. **论据整理**: 各方主要论据和反驳

**证据要求**:
- 起因和关键时间线必须有来源支撑
- 每个主要观点流派需要带来源的摘要
- 未发现对立观点时如实记录，不强行制造流派

### 5. 立场确认

**确认时机**:
- 分析完成后不主动插话
- 等待下一条相关消息触发 Planner
- Planner 必须先调用立场确认动作

**确认流程**:
```
1. 接收去标识化的跨群摘要
2. 评估各方论据和证据
3. 提交立场或中立回退
4. 记录立场依据
5. 之后才能针对该事件回复
```

**立场类型**:
- **明确立场**: 有充分依据支持某一方
- **中立回退**: 证据不足或双方都有道理
- **保留意见**: 需要更多信息

**跨群统一**:
- 同一事件使用统一立场
- 不向群内暴露其他群原文或成员身份
- 只共享去标识化的分析摘要

### 6. 立场维持

**注入规则**:
- 只在相关事件活跃时注入立场
- 归档后不自动注入
- 无关聊天不受影响

**复核机制**:
- 发现重大反证时转入复核状态
- 复核期间恢复中立模式
- 复核完成后再次确认立场（可更新或维持）

### 7. 事件归档

**归档条件**:
- 所有关联群聊连续24小时无相关活动

**归档内容**:
- 完整事件档案（长期保留）
- 未完成分析标记为"未完成"
- 不确认立场的事件也归档

**事件重现**:
- 建立新讨论轮次
- 重新评估，不自动恢复旧立场
- 可参考历史档案但不绑定

## 技术实现

### 模块结构

```
src/chat/group_event/
├── event_tracker.py          # 事件跟踪核心
├── event_detector.py         # 事件检测和聚类
├── event_analyzer.py         # 事件分析引擎
├── stance_manager.py         # 立场管理
├── neutrality_filter.py      # 中立性审核
└── models.py                 # 数据模型
```

### 数据库设计

**events 表** (v44):
```sql
CREATE TABLE events (
    event_id TEXT PRIMARY KEY,
    root_cause TEXT,
    timeline TEXT,  -- JSON
    viewpoints TEXT,  -- JSON
    stance TEXT,  -- JSON
    related_groups TEXT,  -- JSON
    status TEXT,
    created_at REAL,
    archived_at REAL,
    metadata TEXT  -- JSON
);
```

**event_messages 表**:
```sql
CREATE TABLE event_messages (
    id INTEGER PRIMARY KEY,
    event_id TEXT,
    message_snapshot TEXT,
    source_group TEXT,
    source_message_id TEXT,
    timestamp REAL,
    FOREIGN KEY (event_id) REFERENCES events(event_id)
);
```

### 集成点

1. **消息接入**: `bot.py` 和 `heartflow_message_processor.py`
   - 在现有消息处理路径后挂载
   - 通过后台队列异步处理
   - 不影响现有消息流

2. **回复审核**: `reasoning_engine.py`, `reply.py`, `send_service.py`
   - Replyer 生成后审核中立性
   - 在统一发送边界检查事件状态
   - 防止绕过限制

3. **立场注入**: `reasoning_engine.py`
   - 相关事件活跃时注入立场上下文
   - 提供事件摘要和立场依据
   - 不暴露其他群信息

4. **WebUI 展示**:
   - 只读事件档案页
   - 展示摘要、时间线、观点、立场
   - 提供来源引用但不可编辑

### 模型配置

**新增模型任务**:
```toml
[tasks.event_analysis]
description = "事件分析和中立性审核"
default_model = "gpt-6.1-sol"  # 若未配置则继用 utils

max_tokens = 4000
```

**配置版本升级**: v11 → v12

## 测试要点

### 功能测试

1. **事件检测**:
   - 活跃度门槛正确触发
   - 30天基线不足时使用硬下限
   - 同一话题聚类准确
   - 不同事件不误合并

2. **跨群关联**:
   - 同平台账号内 0.85 门槛合并
   - 跨账号/作用域绝不共享
   - 匹配置信度计算准确

3. **中立参与**:
   - 积累阶段允许中立问询
   - 偏向回复被正确重写
   - 审核不通过时使用中性模板
   - 其他输出路径不绕过限制

4. **立场确认**:
   - 分析完成后等待相关消息
   - 缺乏证据时可确认中立
   - 重大反证触发复核
   - 跨群摘要不泄露原文

5. **生命周期**:
   - 无关聊天不注入立场
   - 24小时冷却正确归档
   - 未完成归档正确标记
   - 事件重现建立新轮次

### 性能测试

1. **并发处理**:
   - 后台分析不阻塞消息
   - 多个事件并行跟踪
   - 数据库并发写入

2. **资源使用**:
   - 向量计算不过载
   - 内存占用可控
   - 归档后释放资源

### 边界测试

1. **异常情况**:
   - 模型服务不可用
   - 数据库写入失败
   - 消息格式异常

2. **极端场景**:
   - 超高频消息流
   - 极多跨群关联
   - 长时间运行稳定性
